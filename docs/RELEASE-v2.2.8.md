# v2.2.8 · 接口多了两道保险

**一句话**：内置接口遇到网络不通会自动换官方入口；如果整套接口都失效，还能自动改走你自己部署的接口服务。设置里可以一键体检。

## 两层保险

**第一层：内置多线路**

内置的接口库在加载时就把域名固化了，所以改成「按请求指定域名」——网络层失败时依次切换：

```
interface.music.163.com → interface3.music.163.com → music.163.com
```

三个入口实测搜索 / 歌词 / 音源都能正常返回。切换成功后会记住这条线路 5 分钟，不会每个请求都先撞一次坏线路；重启应用自动回到默认。

**第二层：自建备用服务**

你给的那个仓库（peso12345/NeteaseCloudMusicApi）是 Binaryify 官方库的 fork，代码和接口一致。所以真正意义上的「换一个」不是换库，而是**换一个服务实例**：

- 设置 → 接口线路，填一个自部署的地址，例如 `http://127.0.0.1:3000`
- 内置三条线路全部不通时，同一个调用会自动改走这个地址，参数、Cookie 原样带过去
- 路由规则与服务端一致：`song_url_v1 → /song/url/v1`、`personal_fm → /personal_fm`
- 支持保存后一键「测试线路」，分别显示内置 / 备用的延迟和错误

> 安全提醒：备用地址会收到你的登录 Cookie，请只填自己部署的服务，不要填公共地址。留空就只用内置线路。

## 设置里长什么样

设置 → 接口线路：

- 一个输入框（留空 = 只用内置）
- 「保存」「测试线路」两个按钮
- 状态行，例如：`内置：✓ 480ms　备用：✓ 9ms`
- 内置线路自动切换时，会显示 `（已切到 线路 2）`

## 验证

- 正常状态：内置 480ms、备用 9ms，均通过；搜索正常返回
- **线路切换演练**：把库默认域名改成不可达 → 所有请求自动切到 `interface3`，搜索 / 歌词全部成功，日志只有首次切换记录
- **整体失效演练**：三条线路全部不可达 → 搜索、歌词自动经由备用服务返回（`songs=3`、`lrc=1378`），体检正确显示「内置 ✗ / 备用 ✓」
- 恢复默认域名后重新体检：内置 480ms（默认线路），搜索正常
- 三种布局 × 全部视图冒烟通过，**0 条控制台报错**
