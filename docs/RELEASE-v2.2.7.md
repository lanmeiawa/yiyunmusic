# v2.2.7 · 歌词时间轴更准，搜索更利索

**一句话**：部分歌词「第一句亮很久」「某个字卡着不动」的问题修好了；搜索完搜索面板自动收起，输入框保留关键词，也不再挡住后面的热门推荐。

## 歌词：终于按真实时间走了

### 1. 第一句不再亮十几秒

不少歌词文件开头是制作人员名单，例如：

```
[00:09.00] 企划 : 苏文嫒 张琛
[00:08.00] 母带 : Mai No Label Crew
```

原来只认「作词 / 作曲」几个固定词，漏掉的那一行就顶替了第一句歌词的位置，在前奏里一直亮着。现在这些全部按制作信息过滤，包括「企划 / 统筹 / 录音师 / 混音师 / 母带后期处理录音室 / 第一小提琴 / 总策划 / 特别鸣谢」以及英文的 `Written by:` / `Mastering Studio:`。

抽检热歌榜 40 首：首行是制作信息的从 **11 首降到 0 首**。

### 2. 某个字不再停留很久

LRC 只标了「这一句从什么时候开始」，没标什么时候唱完。原来的做法是拿「下一句开始时间」当结束时间，于是一句 6 个字的歌词，如果下一句在 41 秒后，扫光就要爬 41 秒，看着像卡在最后一个字上。

现在按字数估算演唱时长（中文约 0.3 秒/字，英文按词算，上限 7.5 秒），结束时间取「估算时长」和「下一句开始」的较小值。同一首 41 秒空档的歌，现在约 4 秒扫完，然后正常进入间奏等待。

逐字歌词里单个字如果被标了很长时长（拖长音），扫光最多 1.8 秒走完，不会一个字亮着慢慢挪。

### 3. 顺带处理的源文件问题

- 重复时间戳：同一条时间上的两行会合并，不再有一行永远显示不出来
- 头部 `[offset:±500]` 偏移量：现在会生效
- `[00:12:50]` 这种冒号毫秒写法：可以解析了
- 平台宣传语（`本歌曲来自【青云 LAB】`、`10亿现金激励…`、`业务联系：…`）：不再被当成歌词，也不会在结尾一直亮着

## 搜索：搜完就收起

- **搜完自动关闭面板**：回车或点热搜/建议后立即收起，并且修掉了「输入后快速回车、300ms 后建议返回又把面板弹回来」的问题
- **输入框保留关键词**：搜完不会清空，返回搜索页时也还是这个词，一眼能看清在搜什么
- **面板不再挡住热门推荐**：高度限制到 320px（小窗口按 44% 高度），首页「热门推荐」不会再被完全盖住
- **更容易关掉**：按 Esc 关闭，鼠标在页面上滚动也会自动收起
